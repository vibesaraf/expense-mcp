Auth & Roles

LoginRadius JWT · OAuth 2.1 scopes · RBAC

ℹ️
All protected endpoints require Authorization: Bearer <JWT>. Roles are extracted from LoginRadius token claims. Scopes are extracted from the scope claim. A request can fail auth (401), role check (403), or scope check (403) independently.

Roles

Role Who Capabilities
employee All users (default) Submit expenses, view own expenses
manager Department managers All employee + view/approve/reject team expenses
finance_admin Finance team All manager + view all expenses, generate reports, register users

OAuth 2.1 Scopes

ScopePurposeMin role
expense:submit Submit new expenses employee
expense:view:own View own expenses employee
expense:view:team View direct reports' expenses manager
expense:view:all View all expenses system-wide finance_admin
expense:approve Approve or reject expenses manager
expense:report:generate Generate expense reports finance_admin
📊

Expense Status Flow

Valid transitions between expense states

pending →
approved → paid
rejected

Transitions are permanent. Only pending expenses can be approved or rejected. Once approved, finance can mark as paid.

REST API

HTTP endpoints at /api/* — all require Bearer JWT unless noted

Expenses
POST /api/expenses Submit new expense ▼
Auth
expense:submit employee+

Request Body

categoryIdstringrequired
amountnumberrequired Positive, in currency units
currencystringrequired ISO 4217 (e.g. "USD")
descriptionstringrequired 10–500 chars
expenseDatestringrequired YYYY-MM-DD
receiptUrlstringoptional Valid URL

Response 201

{
  "id": "uuid",
  "status": "pending",
  "amount": 49.99,
  "currency": "USD",
  "description": "Team lunch",
  "expenseDate": "2026-06-12",
  "submittedAt": "2026-06-12T..."
}
GET /api/expenses/me List own expenses ▼
expense:view:own employee+

Query Params

statusstringoptional pending|approved|rejected|paid
fromDatestringoptional YYYY-MM-DD
toDatestringoptional YYYY-MM-DD
categoryIdstringoptional
pagenumberoptional Default 1
limitnumberoptional Default 20

Response 200

{
  "expenses": [...],
  "pagination": {
    "page": 1,
    "limit": 20,
    "total": 42
  },
  "summary": {
    "totalAmount": 1234.56
  }
}
GET /api/expenses/team/:teamId List team expenses ▼
expense:view:team manager+

Path Params

teamIdstringrequired Team identifier

Same query params as GET /api/expenses/me. Response includes submitter info per expense.

GET /api/expenses/all List all expenses — admin only ▼
expense:view:all finance_admin

Additional Query Params

departmentstringoptional
submitterIdstringoptional
GET /api/expenses/:expenseId Get single expense detail ▼
expense:view:own OR expense:view:team OR expense:view:all

Access is further restricted by ownership: employees can only fetch their own expense, managers can fetch team members', finance_admin can fetch any.

POST /api/expenses/:expenseId/approve Approve pending expense ▼
expense:approve manager+

Request Body

notesstringoptional Max 500 chars
POST /api/expenses/:expenseId/reject Reject pending expense ▼
expense:approve manager+

Request Body

reasonstringrequired 10–500 chars

MCP Tools

Model Context Protocol — AI agents call these via JSON-RPC 2.0 at /mcp

🤖
MCP tools mirror REST capabilities but with AI-friendly schemas. Same auth rules apply — the JWT bearer token is passed in the MCP session. Tools validate inputs via Zod before executing business logic.
TOOL who_am_i Get authenticated user profile ▼
✓ No scope required — any authenticated user

Input

No parameters.

Returns

  "fullName": "Alice",

  "manager": { "id": "...", "fullName": "Bob" }
}
